# 1.8.0 功能清理与适配完善

适配对象：Find X7 Ultra / PHY110，PHY110_17.0.0.100(CN01)，Android 17 API 37。版本号 1.8.0，versionCode 13，沿用既有包身份和签名。

## 应用过滤移除

删除分屏与小窗中的“启用应用过滤功能”“使用黑名单模式”、应用列表选择器与对应启动判断。升级连接配置服务时清除旧 `filter`、`blacklist`、`apps` 键，其余设置保留。优先小窗仍保留“排除系统应用”选项，桌面、系统界面等特殊任务继续遵循原生规则。历史版本的审计记录不改写。

## 审计问题 2–7

| 问题 | 实现与边界 |
| --- | --- |
| 2：OCR 可能把商户数字识别为金额 | 在原生 OCR 后验证支付成功、明确金额标签或人民币符号；支持规范小数和千分位。金额冲突、无成功状态、退款或不支持的币种均不提交。保留原生提取链路，不补造金额、收款方或订单。校验绑定本次协程、微信页面与可见窗口；页面已离开或开关关闭时丢弃结果。 |
| 3：短时间同金额交易可能被原生误判重复 | 为原生交易对象附加短期内存证据；两次可见订单号不同，或完整付款时间与其他字段足以区分时，才纠正重复判断。同一交易证据继续去重；证据不全仍采用原生规则，不全面取消去重。证据不写文件或诊断日志。 |
| 4：系统部分恢复微信支持后会遗漏其他页面 | 按 Activity 页面合并。原生已经有效的页面规则优先，模块仅补缺失页面，不因某个页面恢复而取消全部补丁。不改系统规则数据库。 |
| 5：低光保持影响累计显示额度 | 仅拦截本机 `AodUpdateManager$2.hideAodByDarkLight(int)`。不覆盖通用特殊规则判断及其状态，保留原生累计显示额度、遮挡、时段等处理。 |
| 6：关闭一个操作条开关会恢复另一个控件 | 每个 View 分别保存所属开关和原始可见性，在界面线程逐个恢复；仍开启的选项继续隐藏，原本 GONE 的控件恢复 GONE。 |
| 7：兼容与编码校验不充分 | 对当前系统与各宿主版本校验，未适配版本保留原生行为。窗口与 AOD 按功能组检查安装完整性，缺失必需接口时整组透传。投屏只查询本次 `MediaCodec.configure` 实际编码器的 MIME、尺寸与方向；未知编码器保留原生帧率。投屏和手势增加按需运行状态，区分保存配置、接口加载、调用和实际编码配置。 |

## 验证

构建、签名、单元测试和实机结果见 [本版验证摘要](evidence/optimization-1.8.0/validation.json)。历史 1.7.0 的账单详情与扫码付款记录由用户确认保存且金额与收款方正确，不能替代本版新增校验的实测。

本版通过 114 项单元测试，Release 与 Lint 无错误。最终安装包重启后，七个宿主均回复版本与适配就绪。实机同一小窗中，关闭顶部隐藏没有恢复仍被隐藏的底部控件；关闭底部隐藏后再恢复。记账开关关闭／开启在同一进程中恢复原生列表／单项微信入口，原有应用选择保留。

实际投屏选中高通 H.264 编码器 `c2.qti.avc.encoder`，尺寸为 1080×2376，启用增强时配置 60 帧。关闭增强并重连后，电脑正常收到原生投屏画面。用户本轮正常付款反馈弹窗、记账记录、金额与收款方均正常；最终包诊断同时观察到明确金额校验通过、原生 OCR 成功和记账请求被接受。验证资料不包含账单内容或付款页面截图。

运行状态中的“系统接受请求”不等于账单已保存；“已配置帧率”也不等于电脑收到的实时帧率。低光累计额度的完整耗尽实验、全部支付页面及长期功耗均不作通过承诺。
