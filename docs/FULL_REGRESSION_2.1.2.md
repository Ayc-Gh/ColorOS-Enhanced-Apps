# 2.1.2 全面实机回归

本轮覆盖主页的八类功能，发现并修复声音分轨的冷启动失效问题，交付版本为 **2.1.2 / versionCode 18**。主要链路已有实机证据；外观、自由调整比例的补测未得到有效差异，部分长期和场景组合尚未验证，因此本报告不作“全部功能全部通过”的结论。

## 环境与证据范围

- 手机：Find X7 Ultra / PHY110，`PHY110_17.0.0.100(CN01)`，API 37。
- 本轮有效显示配置：1080×2376 / 480 DPI；物理面板为 1440×3168。
- 框架启用本模块及原有 11 个作用域，其他重叠测试模块保持停用。
- 测试日期：2026-11-14。先完成 2.1.1 的关闭／开启／关闭对照，再修复冷启动问题并在 2.1.2 验证主要链路与宿主版本。
- 2.1.2 的功能代码变动集中在声音组件的关联启动处理。未修改的窗口、联网等链路沿用本轮 2.1.1 对照证据，另核对其 2.1.2 接口加载情况；没有宣称所有组合都在最终 APK 上逐一重跑。
- 最后一次构建仅补充投屏重连提示，随后安装并完成九个页面的界面检查。当前安装 APK 与交付 APK 的 SHA-256 一致。

可公开的分项结果见 [脱敏证据摘要](evidence/full-regression-2.1.2/validation.json)。不随源码交付用户账单、取景画面、原始系统日志、设备序列号或私有配置备份。

## 本轮修复

### 声音分轨重启后未自动生效

2.1.1 在没有打开模块管理页的干净重启中，ColorOS 的关联启动管理阻止音效共享进程访问本模块的声音 Provider。旧状态文件仍可能显示先前的“已生效”，但租约对应旧进程，不能作为当前生效证据。

2.1.2 在系统框架内增加精确的调用上下文检查，只处理声音开关开启时、用户 0、UID 1000 的本机音效共享进程访问本模块指定 Provider 的关联名单判断。目标被强停或挂起时不放行，原生前置检查继续执行；不修改系统全局关联启动名单。

重启后观察到新宿主、新租约和原生策略生效；随后验证开关关闭恢复原生应用范围，强停管理应用超过租约期限也会回退，正常打开后重新生效。新增三个边界测试，与现有测试合计 130 项通过。

### 捕获开关切换后的电脑投屏缓存

手机本地截图已经可见时，既有电脑投屏会话仍可能保留“请在手机操作”的敏感页面保护。停止并重新开始投屏后，同一测试窗口能显示。界面及 README 已补充：修改捕获开关后重新打开目标应用，并重连电脑投屏。

这只验证普通窗口的安全标记。硬件 DRM、受保护的解码缓冲区和应用主动隐藏的内容仍由原生机制处理。

## 未证实与未完成项

- **圆角／阴影**：补测请求圆角 0／120、阴影 0／90，当前测试路径的两组画面外观一致。接口加载不等于实际差异已生效；本轮未将这三项判为通过，也未据此断言所有启动路径均失效。系统还会从启动参数及任务缓存读取这些数值，需进一步隔离调用路径。
- **自由调整比例**：自动拖动前后窗口边界未变，开关两侧均没有有效缩放动作。该结果不能证明自由比例有效或无效，需通过有效的原生缩放交互补测。自定义高宽比 2／1.5 已有独立几何证据。
- **窗口高级组合**：顶部／底部控制条的视觉恢复、强制多模式、系统应用排除以及全部数量／横竖屏组合，未逐项完成最终版本行为对照。
- **AOD 长期行为**：没有整夜功耗、长期低光、全部实体单／双击及各初始亮度档位的结论。
- **投屏高级组合**：弱网、游戏、机型降级、全部分辨率与硬件策略组合未穷举；60／90／120 是编码器配置结果，不是稳定传输帧率。
- **记账诊断**：这次用户已确认生成记录，但运行计数没有记录事件，原因尚未确定；本轮不读取金额或收款方，也未重新进行专门支付、全部去重和 OCR 反例测试。
- **声音完全消除**：此前极端增益测试出现全静音或残留，实验修改已撤回；正式包保留原生分轨能力，不承诺算法能完全分离音轨。
