# 电脑与手机多路投屏配套测试

日期：2026-11-13。手机 PHY110，Android 17 / API 37，ColorOS 17.0.0.100(CN01)；电脑 OPPO 互联 17.20.3。

两端配套后，三个不同应用的画面和操作已通过用户对照。四路不能视为稳定上限：四个视频应用滑动时会卡顿并自动关闭；三个视频应用加一个小说应用基本可用，第三个视频偶有轻微卡顿。五路起初可以打开，随后三个窗口卡顿并关闭。

## 修改范围

手机使用独立的“互联多路临时测试”模块，作用域仅为 `com.oplus.linker` 与 `com.oplus.cast`。正式整合模块 1.4.2 的 APK、设置和作用域没有因本次投屏实验改动。

实验同时处理以下路径，而不是只放大能力值：

1. 电脑运行中的 `phoneCast.exe`：临时修改新建、恢复及替换窗口路径的三处活动数量比较值。磁盘 EXE 保持原样，进程退出即失效。
2. 手机互联本体：将应用通道改为独立分配 7237 起的连续端口，保持主画面 7236 独立。复用同一应用的现有通道；用满时拒绝新增，避免原生分配器清空已有记录后回用端口。
3. 手机投屏组件：识别额外端口为应用投屏，处理旧引擎的端口校验及精确状态查询，避免将未知端口回退为主画面状态。
4. 核对端口回收、输入路由与独立虚拟显示。电脑窗口数、标题、缓存画面或瞬时活动列表，均不单独作为成功依据。

实验开关采用临时系统属性，限定 PHY110 / API 37；电脑辅助脚本检查手机配套值、EXE 哈希及原始指令形状，仅在有限测试时段内写入进程内存。该机制尚未成为正式版设置或常驻电脑工具。

## 实测结果

| 配置 | 用户实测 | 可得结论 |
| --- | --- | --- |
| 仅电脑放宽到 5 | 仍只有两应用活动，第三个使较早窗口关闭 | 失败，需要手机配套 |
| 两端三路，早期适配 | 第三个曾显示主画面或别的应用 | 不计成功；已修复反射字段适配及状态回退问题 |
| 两端三路，修复后 | 三个内容正确，可同时刷新、操作；三个视频应用复测无自动关闭 | 本轮三路对照通过；不代表无限时长稳定性 |
| 两端四路 | 四视频滑动会卡顿并关闭；三视频加一小说基本可用，第三视频偶有轻微卡顿 | 只能记为负载相关的实验结果，不作为稳定默认值 |
| 两端五路 | 起初可打开，随后三个窗口卡顿并自动关闭 | 失败，不能标注五路稳定或无限数量 |

三路复测同时采样电脑活动列表和手机三个独立应用的 resumed 显示任务，连续采样约 112 秒维持三路。用户确认三个视频应用持续正常、没有自动关闭。随后记录到远端依次关闭三路以及电脑投屏进程退出；没有将这个阶段计为继续运行，也不从关闭回调反推用户操作。用户的画面和操作反馈用于补足后台计数无法判断的内容对应与输入正确性。

## 仍未确定的限制

投屏组件曾记录 `sig_local_lost`，并随后释放会话；也出现 `remote_closed`。这些回调只说明信令丢失或远端关闭，不能单独证明硬件编码器上限、内存不足、网络带宽不足或电脑解码上限。部分远端关闭还可能来自人工操作。

四路的负载差异说明“能打开窗口”不等于“可同时高负载使用”。没有降低用户画质参数，也没有屏蔽超时、会话释放或资源回收。若继续研究四路视频，需要进一步对照编码参数、电脑解码负载及传输状态；本轮不以关闭错误处理掩盖故障。

## 版本边界

仅对本轮实际安装版本验证；端口类、反射方法与电脑指令地址都不能直接用于其他版本。正式集成还需要两端版本校验、同一上限的配套启停、重连处理及完整恢复入口。当前不应把独立临时模块当作正式版本安装包，也不应仅发布手机 APK 后宣称已解除电脑上限。

原始日志只保存在本地分析目录；公开记录不包含应用内容、账号或网络认证数据。
