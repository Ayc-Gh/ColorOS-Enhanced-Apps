# 独立贴边应用数量

版本：1.4.2（versionCode 8）。设备适配：PHY110 / ColorOS 17.0.0.100(CN01)。

## 使用

打开“分屏与小窗 → 贴边小窗 → 贴边应用数量”，可输入 1–5，留空或选择“系统默认”恢复原生策略。本机原生为 2。新安装和升级都不会自动写入数量覆盖。

新接口需要更新后重启手机加载；此后设置通过现有框架配置同步自动生效。提高数量后，可继续把更多原生小窗收至屏幕边缘。降低数量或恢复默认时，已有的多余贴边应用继续保留；展开或关闭它们后，系统按新上限管理，不自动强退应用。

## 实现

新增配置 `window_capture/edge_count`，与 `window_count` 分别保存。设置入口使用现有整数输入、范围校验和自动保存逻辑，“恢复分屏与小窗默认设置”也会清除此项。

系统框架 Hook 精确匹配 `FloatHandleController.getLimitMaxFloatNum(): int`，同时对直接调用者 `updateInfoMapForAdd()` 去优化，避免原生小 getter 内联后绕过设置。没有写入原生对象的永久字段，也没有替换贴边集合或绕过任务移除流程。

原生新增记录流程只处理 `size < limit` 和 `size == limit`，超过上限时会进入错误分支。因此数量降低后，临时返回不小于现有记录数的上限，保留系统正常的一进一出逻辑。恢复默认后，只有本次运行确实应用过数量覆盖时才进行这一过渡；记录降至原生上限后停止覆盖。全新默认状态完整保留原生返回值。读取不到任务数量时保留原生行为。

数量控制不依赖解除应用限制、强制多窗口、记住贴边或贴边前台保活；这些开关仍各自控制原有行为。电脑 OPPO 互联的应用窗口数量使用另外的流程，本次没有修改。

## 验证

2026-11-13 使用同签名正式包覆盖升级并重启，在 PHY110 上完成以下验证：

| 项目 | 结果 |
| --- | --- |
| 默认透传 | 未保存数量时，原生新增日志仍为上限 2，第三个任务触发原生替换路径 |
| 独立数量 | 仅保存 `edge_count=5`，小窗数量仍未设置，其余窗口增强关闭；5 个不同测试应用均可收至贴边 |
| 图标与展开 | 系统手势日志读取贴边列表大小为 5，展开可见五个图标；点击最早应用后，原任务 41 恢复可见并返回原生小窗 |
| 降低数量 | 从 5 改为 3 后，五个已有贴边图标继续保留；展开一个再收起时，原生新增日志为 `size=4 / limit=4`，未进入集合超限错误分支 |
| 恢复默认 | 四个剩余记录继续保留；关闭测试任务后重新收起三个应用，原生上限恢复为 2，不保留扩大后的上限 |
| 配置与清理 | 收尾配置与升级前逐项核对一致，新设置未保存覆盖；五个原作用域保留，五个测试 APK、测试任务和设备探针已移除 |
| 构建检查 | 62 项单元测试通过，Lint 0 错误 / 26 提示，V2 签名与原版本一致 |

本轮验证的是单用户、当前 ROM、默认原生贴边及展开流程；没有扩大到所有应用兼容性、带五个记录重启恢复、长时间运行、所有旋转姿态和前台保活组合。

结果摘要见 [验证记录](evidence/edge-count-1.4.2/validation.json)。[五个图标保留截图](evidence/edge-count-1.4.2/five-preserved-after-lowering.png) 拍摄于上限已降低为 3、原有五个记录仍保留时。
