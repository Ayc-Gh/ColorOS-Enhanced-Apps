# 微信自动记账适配

适配设备为 Find X7 Ultra（PHY110），ColorOS 17.0.0.100 CN01 / Android 17。本轮使用小布记忆 17.5.2、记账服务 17.8.0（17008000）和微信 8.0.80（3220），LSPosed 2.2.1 / modern API 102。

## 原因与实现

实际负责自动记账的是 `com.oplus.gleanerservice`。本机系统规则保留了 8 项微信页面名称，但对应的自动记账扩展字段均为缺省值 `-1`。原生转换后场景名为空，配置管理器将其排除，因而没有微信入口，也没有相应的自动记账页面监听。

模块针对当前版本的配置转换接口，在内存中复制这些缺省规则并补齐自动记账场景、页面类型和默认开关。系统数据库保持原样，原生转换、版本过滤、应用图标、设置项、识别引擎、金额及支付状态校验、去重与账单保存继续由系统执行。

如果系统已经提供有效的微信配置，保留该配置并移除模块补齐的项目。其他应用、已有有效扩展配置、手动收藏场景和未知页面不做修改。适配限定已核对的记账服务与微信版本；应用更新后需重新验证，不会自动强行套用到未知版本。

只显示入口仍不足以生效：服务初次启动后已有页面监听名单缓存。开关变化时通过系统原有的 `AppSwitchConfigManager.h(Context)` 更新监听；下次读取配置时刷新缓存，关闭后回到原生列表。没有强制放行应用开关或修改总开关。

## 使用与恢复

1. 在 LSPosed 中给模块增加 `com.oplus.gleanerservice` 作用域，升级后重启一次。
2. 在模块“小布记忆”中开启“恢复微信自动记账支持”。
3. 打开小布记忆，进入设置中的“自动记账”，按需开启系统总开关和微信。

模块页面使用与其他入口相同的界面组件，提供运行状态入口。系统自动记账页面以及小布记忆主页面都要求厂商权限，模块显示从桌面进入系统设置的路径，避免提供无法打开的按钮。

初次补齐时微信开关默认关闭；系统已经保存的开关优先。关闭增强不会删除原生开关或历史账单。原生总开关、权限、屏幕信息使用同意、系统运行条件及记账去重均保持原有约束。

## 实测范围

- 增强关闭：系统列表没有微信，支付宝及其他应用正常显示。
- 增强开启：系统列表出现一个微信项目，8 项页面配置进入原生配置链路；第一次出现时微信默认关闭。
- 首轮只恢复入口时，用户打开已有账单及转账后未生成记录。补齐监听刷新后，已有账单详情触发原生提取、必填字段校验及提交请求，用户确认小布记忆出现对应记录。
- 识别与保存沿用原生流程；没有生成测试金额、模拟付款或伪造账单。
- 原生界面与应用开关的关闭、重新开启，以及模块关闭恢复对照，记录在本版验证文件中。

已确认的实际记录来自微信账单详情。用户另反馈扫码支付后没有自动记录，但进入对应账单详情后可正常记录：两条识别流程需要分别适配。实机近期页面记录包含 `WxaLiteAppTransparentLiteUI`，原先的普通控件提取配置不足以覆盖该轻应用结果页。

结果页适配为系统已有的 `PaymentOcrExtractor`：仅在原有已知轻应用结果页和框架支付结果页中启用原生 OCR，不改变账单详情、转账与红包页面的提取配置。识别需同时得到“支付成功”和金额，继续经过原生校验、开关、去重和保存。原生 OCR 轮询限定为 20 次、间隔 1 秒，退出页面按系统原有逻辑结束。

修复后的扫码结果页测试中，用户确认未进入账单详情即出现记账弹窗和对应记录，并确认金额与收款方均正确。技术状态同时记录到 OCR 成功、系统接受请求以及一次原生重复账单拦截。具体计数见本版验证文件。

红包、不同转账结果页和全部小程序页面尚未逐项确认，不将页面名单中有条目视作全部实测通过。当前版本的结果不代表后续微信或系统更新后仍兼容。

## 状态与证据

运行状态显示当前进程的页面触发、原生提取、必填字段命中、提交和系统接受请求次数，另显示控件／OCR 失败阶段与去重。计数不保存金额、收款人、订单号或页面正文，也不在后台轮询。提交或接受请求次数不等于保存成功次数；本轮保存成功另经用户确认。

状态查询使用请求令牌和发送方身份核验。Android 14 及以上的主动查询设置为不延后投递，避免宿主成为缓存进程后长期显示未知。

版本验证摘要见 [validation.json](evidence/aimemory-1.7.0/validation.json)。发布源码不包含厂商 APK、反编译源码、手机数据库、原始私人页面或签名私钥。
