# 2026-11-16 实机审计

本轮直接测试已发布的 **2.1.2 / versionCode 18**。没有替换正式 APK、修改功能代码或发布新版本。测试设备为 Find X7 Ultra / PHY110，系统为 `PHY110_17.0.0.100(CN01)`、API 37。

主要功能已有本轮行为证据，建议继续采用现有架构并做局部修复。优先处理投屏诊断的多进程报告冲突，以及圆角在稳定小窗中的适配缺口；不建议整体重写或为了升级而放宽宿主版本校验。

## 本轮发现

### P2：投屏运行状态存在多进程报告冲突

电脑持续显示合成测试画面，编码器已经按 60 fps 配置时，连续 12 次查询中，7 次返回真实编码器和 `session=true`，5 次返回 `session=false`。这不是根据设置值推测：成功报告包含 `c2.qti.avc.encoder`、AVC、1080×2376、硬件校验上限 120 fps 和实际配置值 60 fps。

`MainHook.onPackageReady()` 按包名安装投屏适配，没有区分主进程与 `:lelinkps`；两个进程均可通过 `AdapterRuntime` 用同一 host 回复。`RuntimeStatusClient` 又只按 host 保存报告，后到的报告能够覆盖已有会话数据。临时测试查询器同样只取最先到达的报告，因此其随机结果也暴露了这个问题。

建议在协议中加入进程名、PID、会话标识和采样时间，按进程保留报告，再明确汇总实际编码进程的状态。增加同一 host 多个回复、乱序回复、空闲进程后到的测试。保留调用者 UID 与请求 nonce 校验。

涉及文件：`MainHook.java`、`CastHooks.java`、`AdapterRuntime.java`、`RuntimeStatusClient.kt`。

### P2：圆角设置在当前嵌入式小窗路径没有稳定效果

重新创建测试小窗、等待画面稳定后，圆角 0 → 120 → 0 的下角区域逐像素一致。早期截图曾出现外观差异，但稳定后不能复现，不能把过渡画面当成设置生效。

原生代码存在任务启动参数、任务缓存和后续图层绘制等路径；当前模块只修改 `FlexibleWindowManagerService` 的取值入口。当前测试启动路径含嵌入式参数，而原生任务实现对此另有分支。现有证据可以确认这条路径的缺口，尚不能确定最终应修改哪一个渲染入口，也不证明所有启动路径都无效。

建议先增加实际任务／图层参数观测，分别覆盖桌面、最近任务及嵌入式启动，再对当前 ROM 的最终绘制路径做小范围适配。验收须比较稳定画面，并验证关闭后恢复。不要直接对所有系统图层全局改圆角。

聚焦阴影 0／90 已有稳定的边缘像素差异，底部横条关闭／开启／恢复也可见。未取得有效的非聚焦阴影和顶部控制条对照，因此不把这两项列为通过。

### P3：声音后台状态写入可以减少

`SoundPolicyRoot` 每秒原子写入状态文件。对同一后台进程连续采样 60.4 秒，`/proc/<pid>/io` 的 `write_bytes` 增加 724,992 字节，约 708 KiB；同时观察到持续的系统调用。

这是进程写入计数，不是电池消耗或实际闪存磨损测量。建议把状态变更和存活检查分开，仅在状态改变时保存文本，并选择较低频率的健康信号。必须同步调整 `SoundController` 的 4／5 秒新鲜度判断，保留 30 秒租约失效后的原生回退能力，不能只修改循环等待时间。

### 诊断与维护的其他改进

- 窗口诊断把比例、数量、自由比例、圆角和阴影归入同一组；组内必需接口通过不能证明每个设置均有效。应提供逐项路径和缺失原因，并明确区分“配置已保存”“接口已安装”“行为已观察”。
- 相册在解析目标接口失败时直接返回，发生在运行状态接收器注册之前；升级后的接口变化可能只表现为未收到回复。相机也在部分反射解析之后注册诊断。可统一为先建立诊断通道，再进行版本和接口检查。
- 相机偏好监听器使用临时 lambda，未像其他适配器一样保存为字段。建议统一持有强引用。本轮没有复现监听器被回收；这是根据 [SharedPreferences 的监听器契约](https://developer.android.com/reference/android/content/SharedPreferences#registerOnSharedPreferenceChangeListener(android.content.SharedPreferences.OnSharedPreferenceChangeListener)) 提出的兼容性改进，不作为已发生的相机故障。
- 记账计数属于宿主进程内的技术状态。应显式报告计数器覆盖情况、进程身份和重置时间，避免把“没有事件”和“没有观测能力”混为一谈。本轮已捕获用户实际操作的事件，因此不把历史上的计数为零继续列作本轮复现故障。

## 测试方法与干扰

证据以开关前后行为、原生状态和关闭后的恢复为准。宿主代码版本和已安装 APK 与正式 2.1.2 一致，核心系统进程在本轮自动回归期间保持原 PID。

一次记账入口检查被其他应用抢到前台打断，未计为产品失败，重新确认目标界面后完整重跑。联网首次使用电脑局域网端点时基线不可达，随后使用公开静态 HTTPS 资源完成实际阻断测试；测试应用的字面响应匹配字段不用于判断该资源的传输成败，传输结果依据完整读取是否抛出异常。

AOD 初次运行受到投屏／唤醒干扰；后续又捕获到距离传感器触发的原生隐藏。两次被打断的计时均不作为通过证据。原生距离保护继续生效，本轮不将其屏蔽以获得测试结果。用户将手机无遮挡平放后，独立重测得到 30.018 秒的有效到期事件。

## 最终恢复与稳定性

本轮基线采集于 13:14，最终恢复核验于 14:17。两组模块配置（包括原先不存在的键）、模块启用状态、11 个作用域和其他模块状态均与基线一致。屏幕超时、旋转、多窗口开发者项、AOD 原生设置及实体手势测试改变的系统开关已恢复。相机的 31 个配置文件逐文件哈希一致，原生记账应用选择未改变，新生成的用户账单保留。

本轮安装的 9 个临时应用全部卸载，设备测试 JAR 和界面转储文件已清理；合成输入图和 AI 输出图按媒体 ID、路径及哈希核对后删除，约 5.8 秒的测试录像已从手机和电脑删除。原始技术证据留在本地分析目录，不作为公开交付附件。

最终 UID 联网规则与测试前一致。声音原生应用属性正确，状态文件新鲜度约 0.6 秒、当前宿主租约约 4 秒；电脑互联显示投屏连接，编码器报告恢复为 60 fps 配置。正常打开模块后保留可用状态，没有重新强停模块来复刻测试前的停止标记。

手机未重启，system_server、SystemUI、音效共享进程、audioserver 的 PID 均未变化；正式 APK 及两项声音系统文件哈希保持一致。崩溃缓冲区中两条 init／crash_dump 历史记录在开始前已存在，没有新增本轮崩溃记录。这不代替长期稳定性验证。

脱敏机器可读摘要见 [本轮证据摘要](LIVE_AUDIT_20261116.json)。

## 重构建议

不做整体重写。已有独立策略类、版本限制、原生回退和 130 项测试值得保留。下一轮先修复投屏诊断聚合，再补齐窗口外观实际调用路径；随后提取共享诊断初始化和声音启动适配，减少 `MainHook` 中跨功能职责。

测试工具需要独立维护：统一前台包名检查、横竖屏坐标、真实操作超时、临时资源归属、失败后的 `finally` 恢复，以及逐进程报告采集。测试工具的失败不应直接变成产品失败，也不应因脚本退出码为 0 就认定所有子项通过。

不建议仅凭依赖版本较旧就全面升级。当前目标是特定 ROM 和宿主版本；系统或宿主更新后，应先收集新接口与行为证据，再扩展适配范围。
