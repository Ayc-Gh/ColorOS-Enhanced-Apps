# 1.2.0：三个设置入口与 AOD 合并

设备：OPPO Find X7 Ultra / PHY110，Android 17，PHY110_17.0.0.100(CN01)。日期：2026-11-12。

## 来源与范围

采用已验证的 AOD 组件 1.11.0，固定源码提交为 `238b2a5633b98041d5942938b41ce282aa4f3c06`。合并的是 Kotlin 实现和设置界面，不通过启动旧应用或依赖旧 APK 提供功能。

保留初始亮度、Android 17 float 运行亮度与旧 int 回退、倍率旁路、全景全天能力、普通超时接管、时长与唤醒取消、单击防误触、低光隐藏策略和按需运行状态查询。没有重写上述算法，也不强制面板刷新率。

## 主界面与配置

- 主界面只有“分屏与小窗”“OPPO 互联”“AOD”三个设置入口。
- 原分屏与小窗设置移到独立页面，设置键不变；其恢复默认只移除窗口相关键。
- “解除截图录屏限制”移到 OPPO 互联页，仍使用原 `window_capture/capture` 开关。投屏优化总开关与截图开关独立；恢复投屏参数仍保留截图开关。
- AOD 页沿用已测试的亮度、功能和运行状态页面。AOD 业务配置为 `aod_config`，状态请求为 `aod_runtime_status`，与分屏/投屏配置隔离。
- 合并应用只注册一个框架服务监听器，并向 AOD 配置存储转发连接与断开事件。状态广播的应用包名、发送方 UID 验证和版本号均切换到合并应用，防止读取旧模块的状态。
- 两个 modern API 入口分别处理原分屏/投屏与 AOD 宿主。作用域合计 system、com.oplus.cast、com.android.systemui、com.oplus.aod。

## 本机迁移

先备份框架配置和旧 AOD 私有设置，逐项核对 12 项本机/远端值一致，再将这组配置通过合并应用自己的配置同步链路写入新模块的 `aod_config`。原 AOD 应用保留安装和配置，启用状态改为停用。旧模块不再注入重启后的宿主。

迁移目标：原暗光 80、亮光 160、倍率备选 1.6；三个“使用系统默认”开关为开启；显示时长为 1 分钟、自定义备选 5 分钟；其他四项 AOD 功能开关保持开启。合并没有沿用早期会话的默认设置覆盖现在的配置。

## 验证

合并构建、签名验证通过；AOD 的 50 项单元测试、投屏的 17 项参数检查全部通过；正式版静态检查 0 错误、26 警告。

实机完成三个入口、AOD 亮度/功能/状态页面打开与配置同步验证。系统界面、系统息屏设置均回复已加载 1.2.0；六项系统界面功能和全天选项均已加载，亮度保持系统默认；实体单击尚未触发不报作手势已验证。原系统框架 62 个挂钩正常加载，投屏组件 11 个挂钩正常加载。

升级并重启后的 OPPO 互联实测已得到 1440×3168、60 Hz 虚拟显示、DPI 560；电脑“手机画面”能显示合并版主界面。原 1.1.0 的分屏、捕获与投屏核心 Java 源码逐字节保持一致。

一分钟 AOD 实测：60.024 秒触发截止事件，随后回放 ColorOS 原生 UI 隐藏路径，60.033 秒结束会话，显示状态为 OFF。另一次会话在约 4.462 秒被唤醒后正确取消定时任务。这里记录的是系统事件时间，不是毫秒级视觉消失测量；原一分钟设置未改动。

完整结果记录于 `evidence/merge-1.2.0/validation.json`。旧版本已完成的长短时长、亮度倍率对照属于历史证据，不当作本次全部重新实测。

90/120 帧、整夜电池功耗、真实面板扫描刷新率、其他 ROM 和实体黑屏全部单双击组合不扩大为已验证。

## 构建注意

Windows 下本次首次在含中文的工程路径运行单元测试时，Gradle 测试进程出现找不到已编译测试类的问题。验证构建改用本机 ASCII 临时路径中的同一份源码；签名沿用原模块，交付源码保持完整。私钥、密码、设备数据库和原始日志不放入源码包。
