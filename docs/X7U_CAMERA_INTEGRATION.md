# X7 Ultra 相机增强合并记录

2026 年 11 月 26 日，独立相机模块 v0.5.0 的稳定功能并入 ColorOS 增强，目标基线为 Git 提交 `3af3868`（v2.1.10）。首个本地候选为 `2.1.11-camera-merge.1`（27），代码复审版本为 `2.1.11-camera-merge.2`（28），后续实机验证采用 `2.1.11-camera-merge.3`（29），仅在电脑端验证的 `2.1.11-camera-merge.4`（30）曾移除 GPU 直出。`2.1.11-camera-merge.5`（31）恢复此功能，`2.1.11-camera-merge.6`（32）增加 SDR 和 HDR 兼容监看预置。候选包使用应用 ID `io.github.oshin.windowcapture`。合并使用源工作区中已恢复到 v0.5.0 的源码。

## 候选六的 SDR 和 HDR 监看

PHY110_17.0.0.100(CN01) 的原厂 `filters_lut` 目录缺少两份监看 LUT。相机继续优先读取固件自带资源。缺少文件时，模块校验 APK 内同名资源的大小和 SHA-256，并按相机当前选项应用在专业视频 Log 的主取景画面。这个固件未启用原厂 LUT 着色器的初始化条件，因此兼容预置复用已实测的监看绘制路径，分别遵循 SDR 和 HDR 的着色器色彩转换规则。内置预置用于取景监看，GPU 直出入口由自定义 LUT 提供。

兼容资源来自 Find X9 Ultra ODM，Find X10 Pro Max ODM 有两份字节完全相同的文件。SDR 表的目标是 BT.709 Gamma 2.4，与 OPPO 官方 O-Log2 对应表的 107,811 个重合通道数值一致。HDR 表对应供体的 BT.2020 HLG 监看。X7 Ultra 的实际 Log 曲线和屏幕 HDR 输出未经校准，首次使用兼容预置时会显示说明。[OPPO 官方 O-Log 下载](https://www.oppo.com/cn/log-to-rec709-download/)

同签名诊断包实测「无 → SDR → HDR → 无」，两种预置均上传到取景渲染器。固定区域的平均 RGB 像素差为无到 SDR 17.3–18.9，无到 HDR 8.5–9.8，首末两次无监看之间为 3.8–5.1，均以 255 为满量程。无监看和两种预置各录一段，均保存 1920×1080 约 30fps 的原厂 HEVC Main 10。自定义 LUT 导入后，监看成片为 10 位 Log，开启 GPU 直出后为 8 位 HEVC，解码画面能测得烧录差异。[实机与构建记录](evidence/camera-merge-2.1.11/lut-monitor-presets.json)

首次从 GPU 直出切到 HDR 已确认取景应用，录制前菜单重新打开并选中了 SDR，测试工具中止该次采样。复跑核对了 GPU 路由释放、HDR 取景和随后录得的 102 帧 Main 10 成片。Release 签名验证、185 项单元测试通过，Lint 为 0 个错误、28 个警告。手机已恢复测试前的候选三和显示设置。[实机与构建记录](evidence/camera-merge-2.1.11/lut-monitor-presets.json)

随后用正式签名包从候选三覆盖升级至候选六，核对安装摘要并完成整机重启。SystemUI 加载版本 32，AOD 在 60.026 秒结束，内屏转为 OFF。声音分轨确认版本 32 的租约续期，关闭后恢复原生范围。关闭相机增强并重启相机后，24fps 和片门全开退出，原有 1080p、4K、SDR 与 Log 入口可用。试验后恢复原开关状态，手机保留正式候选六。[正式包快检](evidence/camera-merge-2.1.11/candidate-6-release-smoke.json)

## 候选五的录像行为

候选五恢复后摄专业视频 1080p30 Log 的 GPU 录像输入、直出开关和功能运行状态。导入自定义 `.cube` 后仅开启取景监看时，原厂录像器保存 10 位 Log。选中 LUT 并开启「GPU 录制效果直出」后，将所选 LUT 写入 8 位 HEVC 成片。候选三的 GPU 音画与旋转标记实测保留在下文。

### 候选五停录修复与复测

GPU 在原厂停止或释放录像器前停止提交新帧，等原厂调用结束后才释放对应的 EGL 输出。释放任务会核对录像归属，避免旧录像的清理影响下一段。

用同签名诊断包在 X7 Ultra 复测。修复前，GPU 输出先于原厂视频轨停止而释放。修复后，三段 GPU 的释放日志均晚于原厂停止返回，间隔约 2、2、11 ms。横屏布局下两段 GPU 连续录制均保存 8 位 HEVC，原厂 Log 保留 10 位。GPU 路径未记录到超过 50 ms 的提交时间戳间隔。

手机物理传感器角度维持 270°。显示角度 90° 的对照组均写入 0° 的 MP4 标记，显示角度 0° 的对照组均写入 −90°。两组中原厂和 GPU 均沿用各自收到的同一原厂录像器参数，未复现组内方向差异。横屏 GPU 样片的容器音轨尾差约为 +210 和 +189 ms，另一个显示布局下约为 +307 ms。原厂样片的尾差也有变化，本次修改只调整 GPU 输出的释放顺序，音轨时间轴仍由原厂处理。

交付 APK 的 Release 构建、同签名核对和 185 项单元测试通过。Lint 为 0 个错误、28 个警告。停录顺序由同签名诊断包实机验证，测试结束后手机恢复候选三。[实机数值](evidence/camera-merge-2.1.11/gpu-stop-fix.json) · [签名与构建记录](evidence/camera-merge-2.1.11/provenance.json)

### 目标工程的运行结构

`app/` 是安装包。设置页通过 `SettingsBridge` 同步 LSPosed API 102 的远程配置，AOD 使用自己的 `aod_config`。各功能按宿主注册独立入口。系统框架负责窗口相关功能，SystemUI 和息屏宿主负责 AOD，手势、流量管理、小布记忆、相机和相册由对应的 ColorOS 应用处理。声音分轨还包含音效和 Atlas 宿主、配置桥接与原生策略恢复。`probe/` 是独立测试应用。

v2.1.10 已有的回归覆盖分屏任务布局、声音策略恢复和微信账单识别。相机合并使用额外的入口类与配置键，因此无需在这些宿主注册相机功能。相机现有的灵感推荐、Log 和滤镜适配仍由 `CameraInspirationEntry` 调度。[目标工程架构与历史记录](PROJECT_HANDOVER.md)

## 配置、适配与恢复

合并模块使用现有远程 `window_capture` 配置组。`camera_x7u_enhancements` 默认关闭。设置页检查设备和相机版本，注入入口还会比对原厂相机 APK 的完整 SHA-256。适配基线是 Find X7 Ultra `PHY110`、`PHY110_17.0.0.100(CN01)`、API 37 和相机 `7.006.191`。相机钩子在进程启动时安装，固件或摘要不符时跳过安装。

大师胶片复用目标 APK 中 17 个 SHA-256 相同的 OEM LUT 文件，继续在相机进程中使用匿名内存文件。大师、普通滤镜使用各自模式与文件映射。Log 仍由原有适配器处理，4:3 使用原有格式状态回退至 1080p。自定义 `.cube` 使用系统文件选择器和会话内存。

1. 记录当前 ColorOS 增强版本、LSPosed 作用域和要保留的设置。若声音分轨开启，先关掉它，等状态显示「已恢复系统原生应用范围」。若独立相机模块在用，先在 LSPosed 停用它，保留安装以便恢复原来用法。
2. 核对候选 APK 的摘要和签名，以同签名包覆盖安装。保留 ColorOS 增强原有的 LSPosed 作用域，包括「相机」。更新包后重启手机，让系统框架、SystemUI 和音效等宿主重新加载。首次解锁后用「功能运行状态」核对宿主版本，再按需要恢复声音分轨原设置。[本地候选包校验记录](evidence/camera-merge-2.1.11/provenance.json)
3. 打开「相机与相册 → 启用 X7 Ultra 相机增强」，强行停止并重新打开原厂相机。以后只改相机开关时也用此步骤。使用自定义 `.cube` 时启用同页的「解锁 Log 视频」，在后摄专业视频的 1080p30 Log 中用「LUT 还原监看」导入和选择。仅监看时，预览显示所选 LUT 的效果，成片由原厂录像器保存为 10 位 Log。需要将 LUT 写入成片时，选中 LUT 并开启「GPU 录制效果直出」。每次重启相机后需重新导入。
4. 撤销新增相机功能时，关闭合并开关，强行停止并重新打开相机。原有 Log、普通滤镜开关继续独立控制各自功能。4:3、自定义 LUT 等会话状态随进程退出。录像中心指示和三类全局曝光的设置保存在原厂相机的专用偏好中，关闭后停止使用，重新启用时可以复用。相册里的成片保留。需要恢复独立版时，先确认合并开关已关闭，再在 LSPosed 启用独立版并重启相机。

如果要恢复整个 ColorOS 增强安装包，先按相同方式恢复声音原生范围并记录设置，再核对要换回的已签名包。Android 可能拒绝用较低 `versionCode` 覆盖较高版本，即使证书相同。若设备没有经过验证的保数据降级路径，卸载重装会清除模块自身数据，之后需要重新核对 LSPosed 启用状态与作用域、恢复设置和所需 Root 授权。仅需关闭相机新功能时无需更换安装包。

为候选三备有本地 `2.1.10-merge-recovery`。它沿用 v2.1.10 基线，同签名且 `versionCode` 同为 29，可从候选三同版本号覆盖恢复。文件只完成电脑端的签名和摘要校验，尚未在手机上安装。[恢复包校验记录](evidence/camera-merge-2.1.11/provenance.json)

## 候选二复审

大师模式和普通滤镜共享部分系统方法，分别处理不同模式、使用不同的匿名文件句柄。大师预览先尝试匹配其资源，成片路径先在返回的原生参数上处理大师 LUT，普通滤镜随后仅处理自己仍能识别的资源。现有 Log 适配负责两项设定的会话值，视频 LUT 负责进程内存储。4:3 仅接受后摄 SDR30，选择 Log 或 HDR 时回到 1080p。静态检查未发现这些功能在正常路径上的设置覆盖或重复启用。独立 v0.5.0 与合并开关同时启用会各自安装钩子，迁移时先在 LSPosed 停用独立版。

| 核查发现 | 候选二处理 |
| --- | --- |
| 普通滤镜的并发渲染可能读取初始化中的 LUT 路径表。 | 路径表完整发布后才由渲染回调读取，反射枚举先核对方法参数数量。 |
| 相机功能部分初始化失败时，已登记的钩子可能残留。设置页也无法指明实际加载结果。 | 安装失败时撤销对应功能已登记的钩子。大师与视频分别初始化，视频设置未能隔离时跳过依赖它的功能。「功能运行状态」区分已关闭、等待重启、固件或 APK 不符、部分加载和失败。 |
| GPU 直出在录制中失效后，旧实现可能继续录音，视频帧停止提交且界面无提示。 | 相机提示停止并重录，失效的 GPU 输入不再用于新录像。重建会话后可回到原厂输入。已中断片段可能不完整。 |
| 本地合并引入三条 Lint 告警，两条是 GPU 提示文案，一条是相机宿主资源查找。 | 文案改用模块资源。大师胶片使用原厂相机字符串，保留按名称查询并仅在该方法记录例外。 |
| 原有 AOD 精确闹钟只有调用失败后的兜底。 | 先检查宿主是否可以调度精确闹钟，无法调度时沿用 Handler。息屏深度休眠下的计时仍取决于宿主可用的调度方式。 |
