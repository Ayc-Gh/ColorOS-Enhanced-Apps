## 系统日志与问题归类

核对了 crash 缓冲、main/system 的 W/E、崩溃／ANR／WTF 事件、DropBox 索引、进程退出历史、ANR／tombstone 文件以及 LSPosed 模块／框架日志。日志直接保存到电脑，没有在手机生成 bugreport 或抓取文件。

- **本轮未发现新增崩溃或 ANR。** crash 缓冲无本轮条目，没有新增 ANR／tombstone 文件，系统记录为自本次启动以来无 ANR。system_server、SystemUI、声音共享进程、audioserver 的 PID 一致。
- **存在错误和警告，不能称为日志完全干净。** 末次保留缓冲有 1669 个 W/E 行头，包含重复记录，不代表同等数量独立故障。早一次事件抓取记录 44 条 JobScheduler 约束映射 WTF；另有一条本模块 XposedService Provider 启动超时和一条原生号码识别组件 Parcel 警告。系统组件还有 invalid flag、统计 provider 缺失、电池 HAL 字符串解析、定位 attributionTag 等错误。
- **测试驱动干扰了模块进程生命周期。** 本模块 W/E 共 362 条，均为声音 Provider 续租错误；退出历史明确记录多次 `start instr`／`finished inst` 的 USER REQUESTED 停止。正常打开模块后恢复，最后一次 DeadObject 告警为 10:46:57，随后正常后台采样全部健康。另对音频跟踪记录完成原生关闭→恢复→原样开启，清除了已卸载测试包名，后续健康检查通过。该现象与测试驱动时序相关，尚未证明是正常使用必现故障。
- **互联仍有诊断警告。** 包括 RTT/Ping 探测失败、接收侧 RTP 统计为空；实际投屏状态仍有 AVC、1080×2376、60 帧编码器。尚无证据把这些警告直接归因于模块冲突或编码失败。
- **没有明确 Hook 冲突标记或本模块非声音适配错误。** 本机同时启用其他 3 个模块，未逐个停用对照，因此不能排除所有隐性相互影响。

### P2 候选：历史声音恢复子进程崩溃

03:17:09 的历史 tombstone 为 `app_process ... SoundPolicyRoot restore`，因 `ClassNotFoundException: io.github.oshin.windowcapture.SoundPolicyRoot` 触发 SIGABRT。命令引用的旧 APK 路径与当前安装不同，现已不存在。结合 `SoundController` 保存 APK 路径后再次启动恢复进程的代码，**疑似 APK 升级／替换后的退出恢复仍引用旧路径**；这是推断，具体升级窗口尚未专项复现。

应优先加固升级退出路径，并专测“旧进程退出时 APK 已替换”的恢复行为。这条记录发生在本轮基线之前，本轮没有新增同类崩溃。另有 02:31–02:35 的 4 次 GMS 历史 SecurityException，提示调用者不是获准的域名验证代理，同样早于本轮。

日志存在轮转，早期事件分类计数与末次保留事件数会不同。保留缓冲、分阶段实时日志及框架日志共同支撑结论，不能以单次空缓冲证明长期无错误。

## 最终恢复与残留

10 个独立临时应用及分阶段重新安装的辅助程序均已卸载；安装数据、编译路径、活动测试 instrumentation 均未发现残留。`/data/local/tmp` 与原始空基线一致。合成输入、AI 输出、Log 视频的媒体行、原路径、回收站副本均复核不存在；电脑临时视频也已删除。音频生产跟踪记录中不再含测试包名。

模块两组配置、11 个作用域、启用状态及其他模块状态与基线一致；屏幕超时、旋转及记录的原生设置已恢复；AOD 恢复局部样式和关闭总开关。相机按用户同意协议后的 25 个配置文件恢复，保留用户的协议选择。首次进入原生记账页由系统初始化了 4 项默认选择，已有选择未被覆盖。

正式 APK、系统声音 XML／库哈希及四个核心进程保持不变；生产状态页在卸载测试器后确认投屏恢复为 60 帧配置。日志和技术证据仅在电脑分析目录，公开摘要不含账单、照片或账号内容。
