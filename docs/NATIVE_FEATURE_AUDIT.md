# 本机原生能力与重复覆盖审计

> 后续修正：本页是 1.4.1 的历史能力与代码审计。2026-11-13 已补做 1.4.2 的模块关闭 / 开启实机对照，见[行为对照报告](BEHAVIOR_AB_AUDIT.md)。原生实际四窗的推断已撤回；原生不可调整大小应用虽能进入分屏，布局处理与模块开启后不同。内部 true 值相同不能代替整项功能的重复判定。原始历史 JSON 保留不改。

报告日期：2026-11-13。设备：OPPO Find X7 Ultra / PHY110，ColorOS 17.0.0.100(CN01)、Android 17。审计对象：ColorOS 增强 1.4.1。报告基于本机配置、隔离只读查询、同哈希系统组件代码、临时测试页面及原生设置页面；审计操作没有主动切换增强开关，也没有修改运行时代码或安装包。收尾发现重新安装记录及配置变化，具体列在下方，不能将整个过程视为不变的全关闭基线。

## 审计基线

起点（11 月 12 日 23:06）只有整合版在框架中启用；窗口、分屏、投屏、捕获与手势解锁开关均关闭。AOD 的全景、全天入口、单击防误触、低光保持均为关闭，时长跟随系统。

但起点 AOD **并非配置上的全部停用**：三个“使用系统默认”均为 false，仍保存暗环境 80、亮环境 160、运行倍率 1.6。进入 AOD 对应流程时，这三项会覆盖系统值。现有设计没有一个覆盖所有 AOD 行为的总开关，读取配置失败时的默认配置也会启用若干增强行为。

收尾读取的安装记录显示，1.4.1 在 11 月 13 日 02:08:03 被重新安装，安装来源为系统安装器。此时 AOD 上述四个增强开关均变为 true，与当前代码的初始默认值一致；三个“使用系统默认”仍为 false，80 / 160 / 1.6 的覆盖保留。手势解锁配置从显式 false 变为未保存，默认仍为 false；窗口、分屏、投屏与捕获开关仍未开启。不能声称模块配置在审计前后完全不变，也不能将当前状态描述为增强全部关闭。

原生 AOD 的 `Setting_AodEnable` 和 `Setting_AodSwitchEnable` 收尾均为 0，所以不将其描述为当前屏幕正在被持续增亮。全天支持发布值在起点和 02:16 读取为 0，收尾为 1；它是可被模块发布的保存值，不能替代面板能力判断。审计未覆盖这些当前配置。若要完全原生的 AOD 对照，需要同时开启三个“使用系统默认”，并关闭其余 AOD 增强、将时长设为跟随系统。

## 内部值重叠与静态候选（不等于整项重复）

| 项目 | 本机证据 | 结论与建议 |
| --- | --- | --- |
| `isPsPlusEnable()` 强制 true | 原生属性读取结果 true，Pocket Studio 与 Panorama Work Branch 查询也为 true | 该单个强制 true 分支重复；不是本机开启多小窗的必要条件 |
| `isAlloawLockFloatPhone()` 强制 true | 原生代码从 `ro.oplus.cfg_fun_flag` 初始化，本机值为 `true` | 该单个许可覆盖重复；不等于其他贴边保活逻辑也重复 |
| AOD 的基础面板全景支持字段强制 true | 面板能力 217 读取成功，值 6，基础全景位 `0x4` 已置位 | `isSupportPanoramicByPanelFeature` 的 true 赋值重复。应将基础支持与全天能力分开，不应因此删除整个全天全景功能 |
| 阻止按机型降低投屏能力 | 同版本机型降级函数中，PHY110 / qcom / SM8650 不命中任何固定降级分支 | 当前静态代码的无收益候选；尚无该开关的电脑投屏开启 / 关闭协商对照，不据此整项删除。它与后续云控覆盖是不同环节 |

## 有条件重复的参数项

| 项目 | 核对结果 | 范围 |
| --- | --- | --- |
| 请求 60 帧 | 原生 VideoFormats 初始请求已经是 60 | 正常协商 60 帧时重复；发生协商降档时强制请求仍可能改变行为。不能据此删除整个帧率控制，也不能将请求值视为实际发送帧率 |
| DPI 跟随手机 | 以本机当前宽度 1080、有效 DPI 480 代入原生 PC 竖屏全宽方法，返回同样的 480 | 原尺寸竖屏场景重复；缩小分辨率或横屏时，原生缩放/档位规则可能与模块不同 |
| 采用硬件实际枚举能力 | 原生已经使用 MediaCodecList 枚举编码能力 | 未降级时重复。模块还可能恢复云控覆盖前的值；本轮动态云控查询失败，不能把整个选项判为无条件重复 |
| 小窗数量设为 4 | 原先仅从一层服务代码推导为原生四窗；后续行为对照发现原生最终只保留两个展开窗口 | 原“设为 4 重复”结论撤回。1.4.2 实机设置 4 后实际保留四个窗口，详见后续报告 |
| 均衡码率、原尺寸等 | 参数策略会保留已经达到所选下限的原生值；相同尺寸也不会被放大 | 可能是无操作配置，不属于新增系统能力；保留“跟随系统”即可避免无谓覆盖 |

当前显示设置为物理 1440×3168 / 640 DPI，覆盖尺寸 1080×2376 / 480 DPI。投屏页面中提到“本机 560”的旧文案已过时；DPI 代码读取当前值，并未写死 560。本轮没有修改显示设置。

## 需要优先复核的模式交互

“强制多窗口模式”会在小窗调用链把原生 false 的 `isSupportMultiMode()` 改为 true。相同系统版本的 `getMaxWinNum()` 首先判断这个标记：true 直接返回 2；false 才继续进入本机 Panorama Work Branch 的四窗路径。

后续实机证明原生最终有效数量已经为两个，单独开启该模式后仍为两个。因此撤回由上述服务分支推导出的“实际四窗降两窗”结论；这些代码分支不能代替完整窗口路径的行为验证。当前只确认该模式在五次测试启动中未增加展开数量，尚不能据此整体删除。

## 其余功能逐项判断

| 功能 | 判断 |
| --- | --- |
| 解除小窗应用限制 | 原生小窗已存在，但应用、调用方及比例限制仍有独立判断。模块扩展这些限制，不等于重复解锁小窗基础功能；对原生已允许的应用无增益 |
| 允许不支持应用分屏 | 临时测试的不可调整大小页面，TaskInfo 的多窗口和分屏支持标记均为 false；可调整大小的对照页为 true。限制仍存在，不宜整体判重复。普通 Intent 支持查询两者都返回 1001，不能用这一项代替任务级判定 |
| 自由比例 | 原生仍按应用列表和具体场景判断可用比例；不是单一全局已开放能力。对本来已支持的应用会重复，对受限应用可能有差异 |
| 比例、圆角、阴影 | 是对原生参数的定制，不能因系统本来有圆角/阴影就认定该功能重复解锁 |
| 隐藏操作条、顶部控制区 | 是界面行为修改；不是开放原生基础小窗能力 |
| 跳转、通知、桌面优先小窗 | 改变普通启动动作的默认选择，和系统已有拖拽/手动进入小窗的触发方式不同。应用过滤、黑白名单、排除系统应用是这些策略的作用范围配置 |
| 记住贴边状态 | 原生虽有贴边任务记录，但 `shouldForceLaunchIfTaskInFloatHandle()` 仍会按记录决定重新启动路径；模块改变该结果。不能仅因系统会保存贴边记录就视为整体重复 |
| 贴边前台保活 | 许可判断的一小段重复，但任务停放、表面恢复及退出路径仍是额外逻辑；不应整项删除 |
| 解除截图录屏限制 | 实机对照：普通测试页色块可被截取，设置 FLAG_SECURE 后相同区域为黑色。限制仍存在，不重复。录屏与实际电脑投屏没有在本轮另起会话验证 |
| 投屏码率、90/120 帧请求、游戏策略 | 参数/场景调整，不能当作原生投屏基础能力解锁。游戏增强仅在组件报告游戏场景时触发；本轮没有重新建立电脑投屏会话 |
| AOD 全天全景 | 面板值 6 不含全天位 `0x8`；全关闭起点的全天支持保存值为 0。全天能力不能视为本机原生已开放项；收尾保存值已为 1，但软件发布能力标记不会改变硬件声明，全天稳定性和功耗另需实际验证 |
| AOD 全天设置入口 | 起点读取保存值 0，模块可改为 1；收尾值已为 1，不能将其作为原生能力证据。入口与后台全天策略是配套的不同环节，不是两个完全相同的开关 |
| AOD 亮度、倍率、时长 | 参数覆盖/超时策略修改，不是重复的基础能力解锁。时长跟随系统时保持原生路径 |
| AOD 单击防误触、低光保持 | 修改原生回调或隐藏规则，属于额外行为策略；本轮未重做实体点击、低光、长时功耗实验 |
| 隔空手势 | 四个扩展 UI 能力原生均为 false。重启手势体感后，实机菜单只有“隔空接听或静音”。新增滑动和暂停/播放入口不重复；原生接听/静音、SensorHub、Explorer 不由当前模块强制修改 |

原系统“隔空暂停/播放”的保存值仍为 1，来自既有系统配置；关闭入口解锁并不自动清除原生功能开关。这不能用来证明该扩展入口是原生默认显示。本轮保留其原值。

## 验证边界与结果文件

分屏请求接口曾返回 true，但测试任务之后仍处于全屏模式 1，故没有将其记为实际分屏成功。接口支持、请求接受、任务能力和最终显示状态分别记录。

运行时 47 个 Java/Kotlin 源文件与已交付 1.4.1 源码包保持一致，已安装 APK 哈希也与交付记录相同。原生手势保存值在审计前后核对不变；AOD 模块配置和全天支持发布值的变化已单列记录。临时测试应用与设备上的探针文件已移除，框架开发者模式仍关闭。本次审计只新增文档和结果摘要，没有生成或安装新版模块。

完整数值与验证边界见 [审计结果摘要](evidence/native-audit-20261113/validation.json)。实际电脑投屏协商、动态云控、全部应用兼容性、全天 AOD 功耗不在本轮通过范围内。
