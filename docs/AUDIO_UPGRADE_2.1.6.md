# 2.1.6：声音恢复进程的升级退出修复

本轮针对 03:17 历史 `SoundPolicyRoot restore` 的 ClassNotFoundException / SIGABRT 做专项修复。设备为 PHY110 / ColorOS 17.0.0.100 CN01 / API 37。修复包已安装并验证；没有重跑与本次改动无关的全部功能。

## 原因与改动

旧启动命令在守护进程结束后，再用启动时记录的 `/data/app/.../base.apk` 路径运行恢复程序。覆盖安装会替换该路径；旧 Java 进程仍可能在运行，但下一次启动恢复或挂载命名空间中的重载程序已找不到类。历史 tombstone 引用的旧 APK 路径现已失效。

修复将代码来源和租约身份分开：Root 外层 shell 启动时只读打开 APK，守护、重载、最终恢复均通过 `/proc/<shell-pid>/fd/3` 读取同一文件。租约仍记录原安装路径和版本；原 APK 删除／版本变化时，旧守护进程照常退出、恢复原生策略。恢复结束关闭文件描述符，不额外长期保存 APK 副本。

专项测试还复现另一处中断：升级使应用读取输出的管道关闭后，守护进程被 SIGKILL 时，外层 shell 可能在报告子进程结束的消息时遭遇断管道，未执行最终恢复。现将外层 shell 的标准输入、输出、错误连接到 `/dev/null`，避免依赖更新前的应用进程。恢复结果继续通过已有状态文件和原生策略查询验证。

改动集中在 `SoundController`、`SoundCompanionCommand`、`SoundPolicyRoot`；原声音功能开关、白名单策略、版本租约和系统文件保护保留。

## 专项验证

| 测试 | 结果 |
| --- | --- |
| 真实 2.1.5 APK 的临时副本删除路径后加载恢复类 | 原路径无法加载；只读固定文件仍可加载。使用捕获异常的探针，未故意制造原生崩溃 |
| 正常退出、非零退出、SIGKILL、含引号和空格路径 | 删除临时路径后，重载和最终恢复均能执行 |
| 音频服务挂载命名空间中重载 | 固定代码文件在路径删除后仍可加载 |
| 输出管道提前关闭对照 | 旧输出连接未到达恢复；分离标准流后到达恢复 |
| 启动前文件已缺失 | shell 受控失败，不启动 Java |
| 最终包正常覆盖安装 | 新安装路径产生，旧路径已删，旧固定文件仍可读；原生策略确认恢复，随后旧描述符关闭、新版本重新生效 |
| 最终包覆盖后强制结束旧守护进程 | 只向核对过命令行和持锁身份的本模块子进程发送信号；原生查询确认 `found=0`，重新开启后恢复 `attribute=3` |
| 后台观察 | 76.67 秒、6 次采样，策略、状态和租约健康，三个标准流均为 `/dev/null` |
| 构建 | 153 项单元测试通过；Release 静态检查 0 错误、33 警告；沿用既有签名 |

最终包的两次真实替换为 versionCode 22 → 22，均确实更换 APK 路径；较早候选另外覆盖过 21 → 22。首个候选仅固定代码文件，强制退出测试暴露输出断管道问题后才补齐分离标准流；首个候选的失败不计入最终通过结果。

03:17 的全部触发时序无法从历史记录完整还原。本轮确认并修复了两种足以中断恢复的具体条件；不声称能在外层 Root shell 本身被杀死或断电时继续运行。已经运行的旧版包装 shell 也无法由新版本追溯修补，首次迁移应让旧声音适配正常退出后再更新。

## 最终状态与清理

当前安装 2.1.6 / versionCode 22，APK SHA-256：`1cb1c2f49e628e54b45bdf9b4ec03662b07951b58d7f773bec4016c1e01a014f`。模块配置、11 个作用域和其他模块状态与本轮基线一致。声音开关恢复原来的开启状态，原生策略及后台租约生效。

为重新加载更新后的宿主模块，曾主动重载一次音效共享进程；手机、system_server、SystemUI、audioserver 未重启。系统声音 XML／库哈希保持一致。本轮没有新增 crash 记录、ANR 或 tombstone。升级期间可见声音 Provider 死对象／暂不可用告警，最终后台观察已恢复。
