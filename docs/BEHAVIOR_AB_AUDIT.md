# 模块开关实机对照审计

后续版本说明：本页保留 1.4.2 的原始结论；启动路径修复、内部恒等覆盖移除及 AOD 开关调整见 [1.5.0 适配优化](OPTIMIZATION_1.5.0.md)。

日期：2026-11-13。设备：Find X7 Ultra（PHY110），ColorOS 17.0.0.100(CN01) / Android 17。模块：ColorOS 增强 1.4.2（8）。

本轮尚未确认有哪一个完整功能可以因“手机原生已经具备”而直接删除。已经确认多项增强会改变实际行为，也确认了少量内部恒等覆盖、两个 AOD 开关在组合使用时的入口重叠，以及需要另行适配的启动场景。后两类不能混为“重复解锁原生功能”。本轮没有删除功能、修改运行时代码或生成新版本。

## 判定标准与基线

按用户给出的标准，原生基础能力是额外设置或行为的必要前提时，不能因为它原本存在，就把整条增强功能判为重复。某个默认数值恰好等于原生值，也不能证明整个可调参数重复。

上午先停用框架模块并重启，取得原生基线；随后启用同一安装包并重启，逐项开关对照。补测时发现用户配置、原生息屏形式和其他模块启用状态已经变化，因此重新记录状态，临时停用另外四个模块并重启，排除其干扰。测试只使用六个临时应用，其中第六个明确声明不可调整大小。

有效显示配置为 1080×2376 / 480 DPI。任务中的 `windowingMode=1` 不能单独证明它是全屏：本机 Canvas 分屏和柔性小窗也可能保留该字段。因此同时核对实际可见任务、柔性场景、客户端尺寸、物理窗口矩形和截图。接口返回成功、支持标记变成 true、菜单出现，均不单独作为功能成功的结论。

## AOD 入口的依赖关系

同一全景形式、原生显示模式为“全天显示”、亮度全部跟随系统，逐组对照：

| 模块配置 | 设置首页 | 实际效果 |
| --- | --- | --- |
| 两个全天开关关闭，时长跟随系统 | 没有“显示设置”，提示持续一段时间后消失 | 约 6–7 秒隐藏 |
| 仅开启“息屏-全天全景 AOD 开关” | 出现“显示设置” | 仍按原生短时隐藏；只出现入口不等于后台全天已生效 |
| 两个全天开关关闭，仅设 30 秒 | 首页仍没有额外入口 | 约 30.02 秒执行隐藏，证明时长控制是独立的实际增强 |
| 仅开启“系统界面-全天全景 AOD 支持” | 已出现“显示设置” | 系统发布全天支持值 1，原生节能隐藏函数报告节能模式已关闭；24 秒内保持显示 |
| 同时开启两个全天开关 | 与上一组首页标签相同 | 单独入口开关未再增加选项 |

因此，“单独入口开关”在后台全天支持已经开启时属于模块内部重叠；后台支持关闭时，它仍能单独暴露入口。不能把整个 AOD 或原生全景基础支持按重复功能删除。是否合并这两个设置，是后续界面与依赖策略的调整，不是本轮已经完成的修改。

## 部分无收益与待适配项

| 项目 | 本轮结果 | 结论边界 |
| --- | --- | --- |
| 强制多窗口模式 | 单独开启后，五次启动仍只留下两个展开柔性任务 | 在该场景没有增加数量；未穷尽模式切换与应用策略，不能整体判重复 |
| 解除小窗应用限制 | 测试用不可调整大小应用，在标准柔性窗口调用下，关闭和开启都可以显示为小窗 | 对这个已被原生允许的测试应用没有增益；尚未验证原生应用黑名单和调用方限制，不能推广为所有应用重复 |
| 记住贴边状态 | 关闭、单独开启时，从桌面重新启动已贴边的测试应用均回到全屏 | 该路径未观察到预期效果，列为适配待复核；不是证明原生已经提供相同的记忆行为 |
| 桌面启动优先小窗 | 普通桌面图标冷启动、已有任务重开，单独开启后均仍为全屏 | 该桌面路径未验证出效果，列为适配待复核，不计作重复解锁 |
| 自定义比例 | 保存比例参数后，实际客户端几何由 1080×1920 改为 1080×2160 | 属于参数修改；本轮不据此确认页面“宽高比”文案的方向正确 |
| 隐藏操作条 / 顶部控制区 | 底部把手在开启后消失；本轮基线中顶部控制区原本未展开 | 底部隐藏有实际差异；顶部单项效果尚未独立验证 |
| 圆角、阴影、亮度、倍率、投屏数值、过滤规则 | 它们控制参数或适用范围，原生本来有圆角、亮度或投屏并不能证明这些调整重复 | 本轮未穷尽每个数值和过滤组合，不把默认值相同当作整个功能重复 |
| AOD 单击防误触、低光保持 | 修改的是唤醒或退出策略 | 本轮未新增实体点击、低光或长时间保持矩阵，不宣称全部通过 |
| OPPO 互联性能策略 | 保留此前组件代码和链路分析 | 本轮未新建电脑端协商对照；60 帧请求等于原生请求值、某次 DPI 恰好相同，都不能证明整个调节功能可删 |

## 内部恒等覆盖与旧结论修正

此前本机只读能力查询已显示：`isPsPlusEnable()`、`isAlloawLockFloatPhone()` 以及面板的基础全景支持为 true。相应“强制 true”的单个分支对本机原值是恒等覆盖，可以作为后续收窄代码的候选；但它们所在的整项功能必须按上面的实际行为分别判断，尤其不能据此删除贴边前台保活或全天全景。

本机机型未命中投屏固定机型降级函数的静态分支，也只是当前代码的无收益候选；本轮没有做该选项的电脑投屏开启 / 关闭协商对照，不将其升级为整项可删除的实测结论。

撤回“原生实际四个小窗”以及由此得出的“强制多模式导致四窗降到两窗”的行为结论：四只是其中一层服务的代码值，原生最终有效限制仍为两个。本轮实际四窗、五窗均需要数量覆盖。保留旧报告及其原始 JSON 作为历史记录，发生冲突时以本报告的行为对照为准。

## 验证边界与恢复

连续主动重启系统界面曾触发 LSPosed 安全模式。该状态下未加载模块的 30 秒样本已经排除，退出安全模式、重新加载后完成了有效的 30 秒补测。桌面选错最近任务、跨应用授权弹窗尚未处理、页面被锁屏或其他系统弹窗遮盖、检测到遮挡传感器隐藏的试次，同样不作为功能成败证据。

原始数据库、完整日志、桌面信息和录屏仅保存在私有分析目录；随报告保存的证据只保留测试应用截图、任务信息、色块数值和必要的 AOD 事件。[脱敏结果摘要](evidence/behavior-ab-20261113/validation.json)记录各项取值。

收尾已关闭各增强开关、清空窗口与贴边数量覆盖，将 AOD 三项亮度控制切回系统默认。后三项在上午起点原本仍保存数值覆盖，此处按用户选择“增强关闭”处理，未声称与上午配置逐字节不变。原生息屏形式与节能选择恢复到下午补测前状态，亮屏超时恢复为此前读取的 30 秒。临时停用的另外四个模块已恢复，安全模式保护设置恢复，最终重启后框架正常加载；七个测试应用和设备探针已移除。安装包、五个作用域与运行时代码均未改变。开发者模式保留下午接手时的开启状态，Hook 调试保持关闭。电脑投屏组件已解除临时强行停止状态，本轮未确认重建了正在进行的电脑投屏会话。具体数值见摘要中的 `restoration`。

本轮没有进行所有应用兼容性、所有黑白名单组合、24 小时 AOD、整夜功耗、硬件 DRM、所有实体手势与单双击、电脑端实际发送帧率的完整测试。尚未验证的项目不当作“原生已具备”，也不当作“确认无问题”。
