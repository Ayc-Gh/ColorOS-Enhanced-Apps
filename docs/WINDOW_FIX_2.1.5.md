# 2.1.5 移除自由调整小窗比例

2026 年 11 月 17 日用户反馈小窗消失，并确认与“自由调整小窗比例”有关，要求删除该功能。

在 2.1.4 与用户当前配置下，以同一测试窗口完成下角缩小操作：自由比例开启时，系统得到 `scale=0.0`；关闭时，同样操作得到原生迷你缩放 `0.24166666`。系统日志同时出现自由比例最小尺寸为 0、目标缩放为 0 和目标布局溢出的记录。原生窗口仍标记可见，但最终绘制缩放为 0，表现为窗口消失。

2.1.3 的自由比例验证覆盖了横向改变宽度及关闭恢复，没有覆盖进入迷你窗口的下角缩小路径。此前的局部通过结论不代表该功能完整可靠，本轮以复现结果更正这个边界。

## 改动

- 删除自由比例设置入口、配置常量、窗口 hook 安装和诊断项。
- 删除放开自由比例支持集合及清空不支持比例集合的覆盖，恢复系统原生计算路径。
- 升级连接配置服务时移除已退役的 `free_ratio` 键，其他配置保留；残留旧键也不会再触发 hook。
- 版本更新为 2.1.5／21，沿用原签名。

安装最终包前先写入旧版 `free_ratio=true`，安装后通过正式配置迁移自动删除，核对其他两组配置保持原样。随后重启手机，移除旧系统进程中的 hook，确认系统框架回复版本为 2.1.5 且不再注册 `Window.FreeResize`。

## 验证与清理

构建与 Lint 通过，0 错误、31 警告；新编译的 32 个测试类、147 项单元测试全部通过。最终包针对下角缩小、迷你恢复和设置移除进行实机验证，具体结果见 [validation.json](evidence/window-fix-2.1.5/validation.json)。未重复相机、AOD、记账或投屏完整流程。

两个测试应用共 6 组下角缩小通过，覆盖左／右下角和 400／650／1000 毫秒拖动。每组都检查操作后及动画稳定后的缩放与边界，原生迷你缩放为 `0.24166666`，展开恢复到 `0.80833334`；没有再次出现 0 倍缩放。设置页已移除自由比例开关，独立的“自定义小窗高宽比”仍保留。

按用户要求，日志只保存在电脑；手机上仅使用本轮登记的临时测试工具和文件，结束后卸载并核对临时目录、测试包私有目录及外部目录无残留。最终清理结果与安装包哈希保存在脱敏验证记录中。

3 个测试应用及其数据已卸载，两个 JAR 和临时界面 XML 已删除；`/data/local/tmp` 恢复为测试前的空目录，测试包列表也为空。其他配置、作用域、模块状态和原生设置与本轮基线一致；最终测试期间核心进程未重启，重启后的崩溃缓冲区没有新增条目。手机保留已安装的 2.1.5，交付 APK 与实机版本哈希一致。
