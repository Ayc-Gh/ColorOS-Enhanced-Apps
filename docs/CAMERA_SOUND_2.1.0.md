# 2.1.0 相机能力核对与声音分轨

实测日期：2026-11-14。设备为 PHY110，ColorOS 17.0.0.100 CN01 / API 37；相机 7.006.191（60000），音效 17.0.18（17000018），声音分轨面板 17.0.07。新增开关均默认关闭，已有设置保留。

## 相机原生对照

原生对照时停用整合模块，临时探针仅记录能力表、资源和实际滤镜列表；后续隐藏项实验与原生结果分开记录。没有修改相机模式数据库。

| 项目 | 本机实测结果 | 本轮处理 |
| --- | --- | --- |
| RAW | 大师模式拍摄格式中可选 | 原生已有，不增加开关 |
| RAW MAX | 大师模式可选，和 JPG、JPG MAX、RAW 同列 | 原生已有，不增加开关 |
| RAW+ | 旧版 super-raw 能力为关闭，与本机 RAW MAX 控制链不同 | 不把 RAW MAX 重命名为 RAW+，未加入 |
| 专业视频 | “更多”中有入口，可进入原生预览及参数界面 | 原生已有，不增加开关 |
| 长曝光 | “更多”中有入口，可进入原生预览 | 原生已有，不增加开关 |

两款滤镜的供体资源已从用户提供的骁龙固件中定位。离屏渲染探针对原生对照滤镜也未取得输出，因此该实验不能用于判定供体滤镜兼容或不兼容。本轮没有把供体 LUT 打入安装包，也没有增加只显示名称的开关；完整资源移植与预览、成片验证仍未完成。

## Log 实现

只对当前已适配相机的 `master_video_mode` 内存功能表补齐缺失的 `com.oplus.camera.feature.logvideo` 注册及其选项。包含主功能键和选项键；只有选项行会导致标签可见、原生支持检查仍返回关闭。

保留已有注册、其他功能、原生分辨率、帧率与功能冲突处理；不强制修改旧电影模式开关，不修改 Log 曲线版本，不替换相机库或固件文件。UI、录制和编码仍由原生相机处理。灵感推荐的配置接口返回值同时按本机真实 `String` 签名修正。

移除临时探针后，整合版已独立验证格式列表和实际录像。样片参数为 1920×1080、30 fps、`video/hevc`、Main10，色彩标记为 BT.709 / SDR transfer；这些标记不能单独证明 O-Log2。开启时使用原生 Log 选择、参数和录制流程，关闭并重启相机后恢复只含 SDR 的原生格式表。测试样片在参数核对后删除，不交付个人画面或录音。

相机功能表在进程启动时构建，开关变化需要重启相机进程或手机。新增 Log 的选择只保存于当前进程；向原生持久存储写入的是 SDR / Log 关闭，原生界面和相机参数通过同一数据层读取当前进程选择。这样既能正常录制 Log，也不会在停用 LSPosed 模块后留下不可见的 Log 状态。重启相机后需要重新选择 Log，已经拍摄的视频保留。

## 声音分轨定位

“声音分轨”属于 `com.oplus.smartmediacontroller.MssService` 的人声／背景声面板，和系统声音设置的“声场扩展”不同。本机 `ro.oplus.audio.support.mss=1` 已具备原生分轨能力，不需要改为 3。

原生限制分为应用列表与底层服务两层。真实策略位于 `/system_ext/etc/Multimedia_Daemon_List.xml` 的 `mss-whitelist`，由 `MMListService` 提供；`SpecailizerPLService` 再校验对应应用的属性位。仅让 Java 白名单判断返回成功，无法保证后端真正放行。

适配使用原生内存策略重载：

1. 系统音效进程加载本模块后，向模块应用续期，Root 授权只由模块应用使用。
2. 核对本机 ROM、音效版本、Binder 描述符、原生策略结构与样本属性；接口不符时不启用。
3. 根据已安装应用补齐白名单位。保留现有属性的其他位、原生已支持应用和所有其他策略段。
4. 在策略服务所在挂载空间短暂绑定读取用副本，调用原生重载后立即卸载。原文件不写入。
5. 关闭开关、宿主退出、续期失效或模块更新时，停止新增应用的分轨并重载原生策略。Root 子进程另有父进程恢复路径。

默认关闭时不启动 Root 适配；开启期间监听宿主存活，新增应用名单定期刷新。运行状态仅记录结果，不记录媒体内容。没有修改空间音效冲突、版权侧分轨幅度、音频输出设备、通话或录音策略。

## 实机验证

- 原生未列入白名单的应用：开启前后端返回 `-1`，开启后返回 `0`，查询状态为启用；关闭后再次返回 `-1`。
- 使用独立本地合成音频测试应用，原生声音分轨面板成功显示。拖动滑块后，原生四路增益查询中的背景声从 100 变为 34；再设为 50 后回读一致，测试后恢复默认。
- 停用整合模块并重启共享声音进程，Root 适配自行退出，白名单恢复，未支持应用再次被拒绝。重新启用并重启声音进程后可再次应用。
- 开关关闭后的系统 XML SHA-256 与抓取原文件一致：`ab631bcdf76aeb055c8574d84ae263a3bc23620749d8e3177605b368d015234d`。
- 临时探针及音频测试应用已卸载；测试开关恢复关闭。

使用原签名构建 2.1.0（versionCode 16）。策略单元测试覆盖白名单位保留、仅修改目标策略段、异常格式拒绝、应用名注入拒绝、宿主失联／重启时的续期失效，以及 Log 当前进程选择和持久存储分离、关闭恢复、不同摄像头隔离；连同已有 Java/Kotlin 测试共 125 项通过。
